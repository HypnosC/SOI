# Chronicles of SOI · 设计 v2（针对「梳理脑中历史结构」重新定位）

> 触发：用户反馈「现在这个 demo 不合我心意」。
> 目标定位：**spacetime notebook for history** —— 不是"历史数据库"，是**帮你把脑中零散的历史印象排成结构**。
> 本文档包含：诊断 → 设计原则 → 数据模型 → 原型 → 可发布 MVP → 对现有代码的具体改法。

---

## 一、诊断：为什么现在的 demo 不合心意

### 1.1 它是「事件录入器」，不是「结构梳理器」

**当前流程：你必须先知道「公元 105 年 / 洛阳 / 34.68, 112.45」，才能把一条记进去。**

这是**填空**。而"梳理脑中结构"这个动作，实际是这样的：

| 你脑子里实际有的 | 当前工具要求的 |
|---|---|
| "春秋战国是一大段" | 一个精确年份 |
| "秦汉之间只隔了十几年，好短" | 两个孤立的事件点 |
| "唐宋之间夹着五代十国" | 又一条孤立记录 |
| "秦灭六国是个结果，前面有一堆因" | 无法表达因果 |
| "同一时期政治在打仗、文化在出圣人" | 全挤在同一条水平线上 |

**方向是反的。** 梳理是"从粗到细、从块到点"；当前工具强制你"从点开始"。

### 1.2 三个致命缺失

**① 没有「时期」这个一级对象。**
历史的骨架是**朝代/时期**（块），不是孤立事件（点）。你脑子里先有"这是一个朝代"，后面才细化到年。当前数据模型里 `TimelineNode = TimelineEventNode`，只有一种节点，**没有 period**。

**② 年份不允许模糊。**
`year: number` —— 只能是整数。但真实历史是模糊的：
- "约公元前 770 年"（平王东迁）
- "前 5 世纪"（孔子活动期）
- "夏，约前 2070—前 1600"（本来就有争议）
**不知道确切年份就不敢录** —— 这是最大的录入摩擦。

**③ Y 轴被浪费了。**
当前 Y 只用来"同年事件错开"（`wy = CARD_BASE_Y + stack * CARD_STACK_DY`）。
而 Y 本该表达**语义**：政治 / 军事 / 思想文化 / 科技经济。
**用上 Y 轴，才能一眼看出"同一时期各领域在发生什么"——这才是"结构"。**

### 1.3 ★ 技术根因：X 与 Y 用了同一个缩放系数

**这是最硬的问题，有代码证据。**

`src/canvas/drawTimeline2d.ts`：
```ts
ctx.translate(vp.offsetX, vp.offsetY);
ctx.scale(vp.scale, vp.scale);        // ← 行、列用同一个系数
```

后果（用当前参数算）：
```
卡片高度 CARD_H = 68px
初始 scale = 0.55        → 屏上 37px   能看
最小 scale = 0.04        → 屏上 2.7px  看不见
轴线 y = 248 (世界坐标)  → 屏上 y = 248 × 0.55 = 136px（缩放后还会跑到顶部）
```

**也就是说：你越缩小想看全局，所有内容就越是缩成一点、挤到左上角。**
**「全览看结构」这个操作在你的 App 里物理上做不到。**

我把这个设计原样复刻成原型试了一次（`prototype` 第一版），结果是：
**整个时间轴塌成顶上一条 30px 的细线，什么都看不清。** 已截图验证。

> **修法：X 与 Y 解耦。**
> X（时间）可缩放可平移；Y（泳道/时期带）用**固定像素布局**，随画布高度自适应，**永不缩放**。
> 这是"结构视图"与"普通无限画布"的根本区别。

## 二、设计原则（针对"梳理"而不是"录入"）

### 原则 1｜时期是一级对象，事件挂在时期下

```
Period（时期）  ← 骨架，先建
  └── Event（事件）  ← 细化，后填
```
界面上一眼看到的是**彩色的时期带**，不是一个空白的坐标轴。
**你想到"春秋"，就先把这根带画上去；想不起细节，就先空着。**

### 原则 2｜年份允许三种精度

```
精确：{ year: -221 }
区间：{ yearStart: -770, yearEnd: -476 }
模糊：{ year: -500, cert: 'approx' }   // cert: exact | approx | vague
```
**视觉表达：**
- `exact` → 实心矩形
- `approx` → 半透明 + 斜纹
- `vague` → 更透明 + 斜纹（"这段我确实不确定"）

**这一条直接消灭了录入摩擦**：想不起确切年份也能录。

### 原则 3｜Y 轴表达领域，且与 X 解耦

```
┌────────────┬─────────────────────────────────┐
│ 时期带      │ 夏 商 西周 春秋 战国 秦 西汉 …    │  ← 骨架（固定高度）
│ 事件密度条   │ ▁▂▃▅▂▁▇▃▂▁▅▂                  │  ← 各朝事件量
├────────────┼─────────────────────────────────┤
│ 政治        │ ●    ●      ●  ●     ●          │  ← 泳道 1
│ 军事        │      ●        ●        ●        │  ← 泳道 2
│ 思想文化    │  ●      ●  ●   ●    ●           │  ← 泳道 3
│ 科技经济    │     ●      ●      ●       ●     │  ← 泳道 4
├────────────┼─────────────────────────────────┤
│ 时间刻度    │ 前2000 前1500 前1000 …          │
└────────────┴─────────────────────────────────┘
```
**泳道高度固定，任何时候都占满画布。** 缩到全览，你看到的仍是 4 条完整的带 + 亮点的分布。

### 原则 4｜多尺度：全览看结构，放大看细节

| 缩放级别 | 你看到什么 |
|---|---|
| 全览（几千年在一屏） | **时期带的形状** + 事件密度分布（哪朝事件多） |
| 中等 | 每个事件的**标题**和年份 |
| 放大 | 事件的备注、详情、关联 |

**标签按缩放级别显隐**（不要在小尺度上硬画文字，会糊成一片）。

### 原则 5｜录入要"一句话"

双击空白 → 一个输入框，接受：
```
-221 秦灭六国 @咸阳 [政治]
```
或者粘贴一段文本，一行一条，批量解析。
**想到什么就记什么，不用填 6 个字段。**

## 三、新数据模型（最小可用，不过度抽象）

```ts
type Certainty = 'exact' | 'approx' | 'vague';

/** 时期：一级骨架 */
type Period = {
  id: string;
  kind: 'period';
  name: string;              // 春秋
  startYear: number;         // -770
  endYear: number;           // -476
  cert: Certainty;           // approx
  color: string;
  region?: string;           // 地理范围（后期接 GeoJSON / bbox）
  note?: string;
};

/** 事件：二级，挂在时期下 */
type Event = {
  id: string;
  kind: 'event';
  periodId?: string;         // 所属时期（可空——想到就先记下）
  title: string;
  year?: number;             // 三种精度，填其一
  yearStart?: number;
  yearEnd?: number;
  cert?: Certainty;
  lane?: string;             // 领域泳道：politics / war / culture / tech
  note?: string;
  placeName?: string;
  lat?: number;
  lng?: number;
};

/** 关联：三级，可选 */
type Link = {
  id: string;
  kind: 'link';
  from: string;
  to: string;
  type: 'cause' | 'sequence' | 'parallel';
  note?: string;
};

type TimelineDoc = {
  version: 2;
  lanes?: { id: string; name: string; color: string }[];
  nodes: (Period | Event | Link)[];
};
```

> **注意 `lanes` 是可自定义的。** 不只"政治/军事/文化/科技"——用户可能想按**地域**分层（中原/北方/南方/西域），或按**维度**分层。**给默认值，但别写死。**

> **注意 `periodId` 可空。** 想到一条事件但还没归入任何时期，也要能先记下来。**不要用外键约束卡住录入。**

## 四、原型（已跑通，见附图）

**文件：** `chronicles/design/prototype-timeline.html`（单文件、零依赖，直接双击打开）

**包含：**
- 24 个中国历史时期（夏 → 新中国），**模糊时期带斜纹**
- 70 条事件，分布在 4 条泳道
- 事件密度条（各朝事件量）
- X 可缩放平移、Y 固定；双击复位
- 真实中国历史数据，不是占位符

**关键验证点：** 缩到全览（时间密度 37.8%），**仍然能看清 24 个时期的完整骨架和 4 条泳道**——
这正是当前 App 做不到的那件事。

**已知待改进（下一步）：**
- 时期名在密集区（五代十国/辽/北宋/西夏/金/南宋）会重叠 → 需要**标签错层**（两行交替或按优先级显隐）
- 密度条左侧"事件量"标签与"夏"带轻微重叠 → 加左边距
- 目前只有时间轴，地图侧还是旧的

## 五、可以发布的 MVP 范围

**判断依据：你想先发布。那就砍到"能证明定位"的最小集合。**

### P0｜不发不行（约占工作量 60%）
1. **时期带**（新增 Period 模型 + 渲染）
2. **泳道**（Y 轴语义 + X/Y 解耦）
3. **模糊年份**（三种精度 + 视觉区分）
4. **一句话录入**（双击 → `-221 秦灭六国 @咸阳`）
5. **本地存档**（IndexedDB 已有，复用）+ JSON 导入导出（已有）
6. **导出长图 PNG**（这个比什么都重要——**用户要能发出去**）

### P1｜第一版之后马上补
7. 事件详情卡 + 备注
8. 搜索 / 跳转年份
9. 上一条 / 下一条（键盘 ←→）
10. **时空联动升级**：时期 ↔ 区域（选"秦"高亮秦的疆域），而不是只有事件 ↔ 单点

### P2｜远期
11. 事件关联连线（你代码里 `PickHit.edge` 已经预留了）
12. 分享链接 / 只读模式
13. 多人协作、多语言

### P0 里最容易被低估的是第 6 条

**「导出长图」是这类工具唯一的传播手段。** 一个人排好自己的历史结构，第一反应是"发出去给人看"。
没有导出，它就是个私人玩具；有了导出，它才可能被传播。**优先级应该排在 UI 美化之前。**

## 八、一句话总结

> **现在的 demo 在回答"我记了哪些事件"。**
> **你要的工具应该回答"我脑子里的历史长什么样"。**
>
> 前者是数据库，后者是**结构编辑器**。
> 差距就是：**时期带 + 泳道 + 模糊年份 + 能缩小看全局**。
