# Chronicles of SOI · 设计 v4：边读边记，长出历史观

> 用户澄清：「从大的说可以录入已知的历史；从小的说，可以让一个人边读历史书，边写自己的笔记，然后形成自己的历史观。
> 我一开始的出发点是我历史比较差，然后没有切入点，看了一些历史，也记不住，感觉需要系统的梳理一下。」

**这句话把产品从"历史地图浏览器"变成了完全另一个东西。本文档按这个重写。**

---

## 一、先说结论：这是目前最好的定位

**理由三条：**

1. **它解决的是你自己的真问题**——"历史差、没切入点、记不住"。**自己的痛点是最好的产品起点**，因为你既是产品经理也是用户，能天天验证。
2. **这个交叉点是空的。** 笔记应用（Obsidian / Notion / Logseq）**没有时空坐标**；历史地图（Geacron / Historic Borders）**不能写笔记**。两边都不覆盖这个位置。
3. **它天然产生护城河**——你用三个月，里面就有一份别人拿不走的东西：**你自己的历史结构**。

**但前提是：不能做成"更好的地图"。必须做成"一边读一边长结构"。**

---

## 二、把"历史差、记不住"拆成两个真问题

### 问题 A：「没有切入点」——不是没有知识，是**没有锚**

历史是一条没有边界的河。新手不知道从哪一只脚下水。
**"切入点"的本质是"锚"**——把新的东西挂到一个已经稳的桩上。

**三种锚，按有效性排序：**

| 锚 | 怎么做 | 评价 |
|---|---|---|
| **关系锚** ★最有效 | 把**你已经记得的东西**先摆上，然后往外挂 | 你历史差，但**中学课本的朝代顺序你一定记得**：夏商周秦汉三国两晋南北朝隋唐宋元明清 |
| **地理锚** | "我住的这地方，历史上发生过什么" | 最直观，但需要数据支撑 |
| **时间锚** | "我出生那年，世界在发生什么" | 有意思但覆盖窄 |

**所以冷启动不该给空白画布，应该给一副骨架。**

> **关键洞察：你觉得"历史差"，但"夏商周秦汉三国两晋南北朝隋唐宋元明清"这个顺序你是会背的。**
> **那副骨架就是你的切入点。先摆上它，之后每读到一个点，就往里挂。**

### 问题 B：「记不住」——不是记忆力差，是**没有结构可挂**

认知科学上的常识：**孤立信息记不住；挂在已有结构上的信息才记得住。**

**传统笔记的病根：记在纸上，但纸不会告诉你「这条和你三个月前记的那条有关系」。**
所以你记了 200 条，它们还是 200 个孤岛——**记了等于没记**。

**所以工具的核心职责不是"存"，是"挂"。**

> 记下一条 → 工具**主动**把三条线索推到你面前：
> 1. 时间上挨得近的（你已经记过什么）
> 2. **同一个地方的**（这里以前发生过什么）
> 3. **同一时间的另一个世界**（别的地方同时在发生什么）

**第 3 条是最有魔力的**——你记「1587 万历十五年」，工具告诉你「1588 英国击败无敌舰队」。
**两个你原本永远不会连起来的东西，被时间轴自动接上了。** 这就是"历史观"开始长的地方。

---

## 三、核心循环：记 → 挂 → 长结构

```
    记 Capture           挂 Attach               长结构 Grow
 ┌──────────────┐   ┌──────────────────┐   ┌──────────────────┐
 │ 一行文字      │ → │ 自动关联三条线    │ → │ 时间轴 + 地图     │
 │ 年份+标题+地名 │   │ 近 / 同地 / 同期世界│   │ 结构自己浮出来    │
 └──────────────┘   └──────────────────┘   └──────────────────┘
```

**"历史观"是积累的自然结果，不是一个功能按钮。**
你要做的只有一件事：**读的时候顺手记一行**。

## 四、三个设计决策（都为了降低摩擦）

### 决策 1｜录入摩擦降到一行字

```
1587 万历十五年 @北京
```

- **年份可模糊**：`约1581` / `1580s` / `16世纪` —— 想不起确切年份也能记
- **地名可省**：`@北京` 不是必须
- **不要求分类**：不选主题、不选朝代、不填标签
- **允许先记下、以后再归类** —— 分类是负担，负担会杀死记录习惯

> **一条铁律：如果记录一条需要超过 5 秒，这个产品就死了。**

### 决策 2｜记完立刻「挂靠」，而不是等你以后整理

上面那张截图就是这个。每次记完，右侧立刻出现三组关联。
**这是唯一能治"记不住"的机制**——你不需要回忆，工具把关系端到你面前。

### 决策 3｜课本骨架做冷启动

第一次打开不是空白，是**一副摆放好的朝代带**。
你可以在上面直接开始挂；也可以换成别的骨架（世界史、某个地区、某个主题）。

## 五、原型（已跑通）

**文件：** `chronicles/prototype/notebook/index.html`（单文件、零依赖、**双击就能开**，不需要服务器）

**包含：**
- 顶部：20 个朝代的**课本骨架带** + 你记的点
- 中间：一行输入框（`1587 万历十五年 @北京`），带模糊年份解析
- 左下：**挂靠面板**（近邻 / 同地 / 同期世界 三组）
- 右侧：你记的全部条目，按年份排序，用朝代颜色标记
- 预置 12 条（假装你正在读《万历十五年》）

**实测：** 输入 `1587 万历十五年 @北京` 后，立刻得到——
```
▲ 时间上挨得近的
   1588 英国击败无敌舰队            1 年后
   1592 壬辰倭乱（援朝抗日）@朝鲜     5 年后
   1575 海瑞复出 @南京              12 年前
▲ 同一个地方你还记过
   1601 利玛窦进京传教              14 年后
   1421 迁都北京                   166 年前
▲ 同一时间的另一个世界
   1588 英国击败无敌舰队            1 年后
   1558 伊丽莎白一世即位            29 年前
   1533 阿克巴继位莫卧儿            54 年前
```

**已知不足：**
- 没有"书名 / 来源"字段（哪条笔记来自哪本书）
- 没有摘录（原文引用）
- **地图侧还没有接上**（空间锚只存了地名，没落到地图）
- 没有搜索

## 六、前面几版的角色重排（不是推翻）

v3 那个"时空块 + 框选查询"的原型**不浪费，但角色变了**：

| 组件 | 原来的角色 | 新角色 |
|---|---|---|
| 历史疆域数据集 | 要展示的内容 | **"借底稿"的来源**——想画一个疆域时不用手绘 |
| 框选查询 | 主要功能 | **地理锚**的实现——"我住的这块地方历史上有什么" |
| 时空块 | 主要对象 | **你自己笔记的容器**——笔记挂到块上 |
| 时间滑块 | 主要交互 | **回看**——看看自己积累的这几个月覆盖了哪些年代 |

**一句话：数据集从"内容"降级为"底稿"；你从"读者"升级为"作者"。**

**判断依据：你想先发布，且时间被上班和软考占着，方案必须小步。**

### P0｜首发必须有（约 2~3 天）
1. **一行录入 + 模糊年份解析**（原型已有 ✓）

4. **本地存档**（IndexedDB，代码已有可复用）
5. **导出一条笔记的图片**——你读到好的一段，能发出去

### P1｜首发后马上（约 2~3 天）

11. 时空重叠检测（你的笔记之间互相矛盾时提醒你）

## 八、三个诚实的提醒

**① 这个产品最难的不是技术，是"你还会不会继续记"。**
第一周记 30 条很容易；第三周还在记才是考验。
**所以 P0 里"导出一条笔记的图片"其实比看起来更重要**——它给你即时回报。

**② 别加功能。** 你的 Ponytail 风格是对的。
这个产品的价值在"记的摩擦足够低"，任何额外字段都会提高摩擦。
**书名、摘录、地图，都放到 P1——先把"记账"这件事跑顺。**

**③ 你现在有 14 天后的软考。**
这条我不再多说，只提一次：**这个设计已经写完了，可以放着。** 考完再动手，不会过期。
如果现在就要动，**只做 P0 的第 5 条（导出图片）**——半天，但能让产品立刻"能给人看"。

## 九、一句话总结

> **你历史差、记不住、想系统梳理。**
> **解药不是"读更多历史"，是"一边读一边把读到的东西挂到一个会自己长大的结构上"。**
>
> 这个结构，就是你的历史观。
> **工具要做的事只有一件：让"挂"这个动作自动发生。**
