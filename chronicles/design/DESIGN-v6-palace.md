# Chronicles of SOI · 设计 v6：记忆宫殿

> 用户原话：「地图不是目的，可是光一个时间轴我感觉太单薄了，最好地图还能放大，可以挂图片，视频等等。
> **记忆宫殿的味道。**」

---

## 一、重新定位：这就是「记忆宫殿」

**Method of Loci（位置记忆法）是人类已知最强的记忆术**，原理一句话：

> **空间记忆比抽象记忆强一个数量级。**

**而它正好治你的病**——你说「我历史差、看了记不住」。
不是记性问题，是**你把历史当成了一条线**（时间轴），而大脑记不住线，**大脑记的是房子**。

### 记忆宫殿的四条原理 → 产品里的四个功能

| 记忆宫殿原理 | 产品功能 | 原型状态 |
|---|---|---|
| ① 用一个**熟悉的空间** | 地图，**或者你自己上传的照片**（你家、教室、上学那条路） | ✅ 已做「换场景（上传图片）」 |
| ② 把东西**放在具体位置** | 在空间任意位置**钉卡片** | ✅ 点击即钉 |
| ③ **图像优先于文字**（越夸张越好记） | **卡片挂图片/视频**，文字只是标注 | ✅ 已做「挂图片」 |
| ④ 按**固定路线**走一遍才能召回 | **时间轴就是那条路线** | ✅ 底部时间轴 |

**你说"地图不是目的"——这句话是关键。地图只是一个容器，而且这个容器可以换成任何东西：**
- 中国地形图（默认）
- **你家客厅的照片**
- 你学校的平面图
- 一张白纸

**"记忆宫殿"的核心技术形态就是：一个可无限缩放的空间容器 + 钉在里面的多模态卡片。**

---

## 二、「光一个时间轴太单薄」——解法是卡片，不是更多轴

时间轴单薄的根因：**它只有一维，而且只能放文字。**

记忆宫殿里的"记忆"长什么样？**是一张荒诞的、彩色的、立体的画面**——不是一句描述。

所以产品的原子单位不该是"事件文本"，该是**卡片**：

```
一张卡片 =
    一个空间位置 (u, v)          ← 钉在场景里
  + 一个时间（或时间区间）         ← 挂在时间轴上
  + 一个文字标签                   ← 只是索引，不是内容
  + 一张图 / 一段视频 / 一段音频    ← 真正的记忆载体
```

**同一张卡片，两个投影：**
- 在**空间**上，它是一个图钉（放大后展开成图片）
- 在**时间轴**上，它是一个点（有图的话点上方有个小绿点）

**这就是"时空笔记本"的完全体——不是一条轴加一张图，是"可挂一切的空间 + 一条路线"。**

---

## 三、「能放大」的真正意义：不是 UI 缩放，是**认知缩放**

这一条我要单独说，因为它是记忆宫殿体验的核心。

```
全国  →  省  →  市  →  街道  →  一栋楼  →  房间
 5%      50%     200%    800%     3000%    10000%
```

**每放大一层，就是往宫殿里走深一步。**

**原型里已经体现了这个原则：**
```js
// 放大到 90% 以上才显示图片缩略图；否则只画一个"这里有一张图"的小绿环
if (c.img && view.k > 0.9) { ...画缩略图... }
else if (c.img) { ...画一个小绿环... }
```

**这就是"走近了才看得见细节"。** 远看是结构（哪些时间点有东西），走近了是内容（图片、细节）。

> **普通笔记软件的做法是"点开才看得到"。**
> **记忆宫殿的做法是"走近就看到了"。** 这个差别决定了它是不是"宫殿"。

## 四、技术设计

### 4.1 场景 = 一张底图（可替换）

```js
baseImg = <canvas 或 Image>     // 默认：程序用真实海岸线画的 4096×2560 地形图
view = { ox, oy, k }            // 视口：平移 + 缩放(0.05x ~ 12x)
```

**换场景 = 换一张图。** 用户上传自己的照片，`baseImg` 换成它，`bb()` 重新适配视口。
**所有的卡片位置是归一化坐标 (u,v) ∈ [0,1]²，所以换场景后卡片按相对位置重新落位。**

> **一个设计选择要说明**：归一化坐标意味着"换场景后卡片会漂"。
> 更严谨的做法是**双坐标**：`(u,v)` 用于显示，`(lng,lat)` 用于跨场景不变。
> **建议**：如果场景是真实地图，存经纬度；如果是自定义照片，只存 (u,v)。**如果 (lng,lat) 存在，则任何场景都能落位。**

### 4.2 卡片 = 多模态

```ts
type Card = {
  id: string;
  u: number; v: number;          // 空间位置（归一化）
  lng?: number; lat?: number;    // 可选：真实经纬度（跨场景稳定）
  year?: number;                 // 时间（可为区间：yearStart/yearEnd）
  text: string;                  // 标签
  place?: string;                // 地名
  media?: { kind:'image'|'video'|'audio'; src:string; poster?:string }[];
  note?: string;                 // 备注（可放原文摘录）
};
```

**`media` 是数组——一张卡片可以挂多张图。** 这对记忆宫殿很重要：
一个地点你可能有一张古画、一张现代照片、一段视频。**三张图放一起，对比本身就是记忆。**

### 4.3 「视频等等等」怎么存

| 媒体 | 存储方式 | 缩略图 |
|---|---|---|
| 图片 | IndexedDB 存 Blob | 直接缩略 |
| 视频 | IndexedDB 存 Blob（几 MB 可行） | 取第 1 帧 or 用户指定 poster |
| 音频 | IndexedDB 存 Blob | 波形图 or 时长徽标 |
| 网页链接 | 只存 URL | OG image（需要抓，可以先不做） |

**IndexedDB 存 Blob 是标准做法，几十 MB 没问题。** 但如果要大量视频，考虑：
- 只存**文件路径引用**（Tauri 桌面可以，网页不行）
- **你用的是 Tauri** → **可以直接引用本地文件路径，不用把视频塞进数据库。** 这是 Tauri 相对网页版的优势。

### 4.4 一个必须解决的问题：**卡片重叠**

原型里已经出现了：长安、洛阳、开封几个地方距离很近，放大后**卡片糊成一片**。

**解决方向（按实现成本排序）：**
1. **缩小时只画点，放大时才画卡片**（已部分实现）
2. **同一位置的多张卡片聚成一个"堆"**，点开才展开（像地图聚合）
3. **标签避让**：沿法线方向推开
4. **手动微调**：允许把卡片拖离锚点，用一条线连回锚点（设计工具里的惯例）

**建议：先做 1 + 4。** 2 和 3 是后续优化。

## 五、原型现状

**文件：** `chronicles/prototype/palace/index.html`（单文件 + `land.js`，双击就开）

**已实现：**
- ✅ 场景可缩放 5%~1200%（滚轮，以光标为锚点）
- ✅ 场景可平移（空格/中键拖动）
- ✅ **换场景：上传任意图片作为底图**
- ✅ 点击空白钉卡片（文字 + 年份，支持 `约-221` / `1580s`）
- ✅ **卡片挂图片**（选本地文件，FileReader → 画在画布上）
- ✅ 放大到 90% 以上自动显示图片缩略图
- ✅ 拖动卡片改位置
- ✅ 底部时间轴 + 可拖动游标（年份 ±120 内算"存在"）
- ✅ 都城迁移虚线（长安→洛阳→开封→北京的路线）

**已知不足：**
- ❌ 没有持久化（刷新就没了）
- ❌ 视频/音频还没做
- ❌ 卡片重叠没解决（上面 4.4）
- ❌ 没有触摸手势
- ❌ 换场景时卡片会漂（因为只存了归一化坐标，没存经纬度）

---

## 六、建议的开发顺序

```
第 1 步（半天）  持久化（IndexedDB）
  → 存 cards + 场景图 + 视口。没有这一步，你不会真的开始记。

第 2 步（半天）  卡片重叠：允许卡片拖离锚点 + 拉一条线回锚点

第 3 步（半天）  视频 + 音频挂载（Tauri 下直接引用本地路径）

第 4 步（半天）  双坐标：卡片同时存 (u,v) 和 (lng,lat)

第 5 步（1天）    卡片堆 / 聚合
```

---

## 七、一句话

> **你要的不是"一个历史时间轴加一张地图"。**
> **你要的是"一个可以无限走进去的空间，里面钉满了带图的东西，还有一条按时间走的路线"。**
>
> **前半句是记忆宫殿，后半句才是时间轴。**
> **时间轴不该是主体——它只是你穿过宫殿时走的那条路。**
