# Chronicles of SOI · 设计 v3：真正的「时空」，而不是「更好的时间轴」

> 触发：用户指出「你设计的是 timeline，没有空间方位上的对应。时间线工具现在有的，我想做创新的。」
> **这个批评是对的。本文档先承认问题，再重新定位创新点。**

---

## 一、先承认两件事

### 1. v2 设计的是「更好的时间轴」，不是「时空」

v2 我加了**时期带 + 泳道 + 密度条**——这些都是**时间轴内部的改进**，
**地图完全不在设计里**。而"时空笔记本"的地图不是附属面板，是**另一半本体**。

### 2. 更重要的：「时间滑块 + 历史地图」这条路，**已经被做完了**

数据集 README 自己列了同赛道的产品（[来源](https://github.com/aourednik/historical-basemaps)）：

| 产品 | 做什么 | 已实现 |
|---|---|---|
| [Geacron](http://geacron.com) | 公元前 3000 年至今的交互式世界历史地图 + 时间轴 | 时间滑块看疆域 |
| [Historic Borders](https://historicborders.app/) | 时间轴 + 历史边界，还有 3D 地球视图 | 同上 + 地球 |
| [Point in History](https://hanshack.com/point-in-history/) | 点地球上任意一点，看该点的历史 | 地点时间剖面 |
| [Atlas Pi](https://atlaspi.it/) | 1000+ 政体的 GeoJSON + 事件 + 朝代链，4000 BCE–2024 | 数据 + API |
| [Ourednik 的投影探索器](https://ourednik.info/historicalmaps/app.html) | 同一数据集在不同投影下的探索 | 投影实验 |

**所以：如果我给你做"拖动时间看疆域变化"，那就是在抄 Geacron。这不是创新。**

---

## 二、那么空白在哪？——「地图册」与「笔记本」的区别

把上面五个产品放一起看，它们的**共同特征**非常清楚：

| 特征 | 现有产品 | 你要的东西 |
|---|---|---|
| 数据来源 | **别人做好的权威数据库** | **你自己的理解** |
| 交互方向 | 单向：**查** → 看 | 双向：**写** ⇄ 看 |
| 核心对象 | **某年的地图快照** | **一个时空块：时间段 × 空间范围** |
| 不确定性 | 无（数据就是对的） | **一等公民**（"这段我不确定"） |
| 价值主张 | 地图册：**数据准确** | 笔记本：**结构清晰** |

### 一句话定位

> **Geacron 是地图册（atlas）——你查它。**
> **Chronicles of SOI 应该是笔记本（notebook）——你写它。**

**地图册的价值是"数据准确"；笔记本的价值是"结构清晰"。**
「梳理脑中历史结构」要的是后者。

**而这个赛道上，我在公开产品里没找到做"笔记本"的。**

## 三、原型：三个现有产品没做的事（已跑通）

**文件：** `chronicles/prototype/spacetime/index.html`
**数据：** [`aourednik/historical-basemaps`](https://github.com/aourednik/historical-basemaps) 17 个年份快照（前 2000 → 2000），18.7 MB
**运行：** 起本地静态服务（fetch 读 geojson，`file://` 会被 CORS 拦）

```bash
cd chronicles && py -m http.server 8765
# 打开 http://localhost:8765/prototype/spacetime/index.html?year=1200
```

### 创新点 ①：把「年快照」反解成「时空块」

**现有产品给你的是 200 张地图。**
**我给的是：每个政权的存活区间。**

同一个数据集，两种本体（ontology）：

```
Geacron 的本体：Snapshot  —— 「公元 1200 年的世界政治地图」
我的本体：      Volume    —— 「宋帝国：960 → 1279」（一条区间）
```

**界面上就是右侧那一列"时间条"**：每条 = 一个政权在本数据集里的存在跨度。
时间轴上的一个单位**不是点**，是**区间**——**这就是"块"，不是"轴"。**

> 这个转换技术上很简单（把每个 NAME 出现的年份收集起来，取 min/max），
> **但本体换了，产品就换了。**

### 创新点 ②：框选式时空查询（画框，不是打字）

**在地图上拖一个矩形 → 得到「曾出现在这个区域里的所有政权」及其时间跨度。**

原型的实测结果（截图 2）：在华北画一个框，结果是——
**西夏 / 宋帝国 / 辽 / 蒙古帝国 / 高丽**，以及它们各自的存活区间。

现有产品是：**某一年 → 某地**（一维时间 × 空间）。
这是：**跨所有时间 × 跨一块空间**的**二维查询**。

> **你不需要记得"哪些政权在华北待过"——工具告诉你。**
> 这才是"梳理"：不是回忆，是**让工具把结构摊开给你看**。

### 创新点 ③：「时间幽灵」——跨年份的叠加，而非快照切换

被框选/选中的政权，**在其他年份的疆域以淡影保留**，当前年份画实色。

一眼看出：**这块地方以前是谁的、后来变成谁的、什么时候换的手。**

Geacron 的模式是"切换快照"（一次看一年）；这是**时空叠加**（同时看到多层）。

### 原型的其它组成部分

- **地图**：Canvas 手绘等距圆柱投影，聚焦东亚（lng 68–146 / lat 12–56），零地图库依赖
- **时间滑块 + 播放**：拖动或自动播放，疆域连续变化
- **右侧时空块列表**：按存活起点排序，条上有一条金色竖线标"当前年份"
- **URL 参数**：`?year=1200` / `?box=105,28,125,42` / `?pick=Song Empire`，便于分享与截图

**已知不足（下一轮）：**
- 数据粒度是世界尺度，**中国的五代十国 / 十六国这一层没有**（只有 Song / Liao / Xixia / Jin / Mongol）
- 政权名是英文，需要中文映射表
- 只有 17 个年份，中间年份是"跳变"而非渐变
- 还不能手绘疆域（这是"笔记本"的关键，见下）

## 四、还应该做、且是真正差异化的四件事

### ④ 时空重叠检测 ★最该做

**两个政权的时间区间重叠 + 空间范围重叠 → 自动标注"曾共存 / 曾争这块地"。**

比如：南宋 与 金 的时间区间重叠、空间南北相邻 →
工具直接告诉你「1127–1234 之间，这两家同时在，边界在淮河一带」。

**现有产品全都不做这个**——因为它们是"权威数据展示"，不需要检测冲突。
而**个人笔记本恰恰需要**：你记的东西可能自相矛盾，工具应该帮你发现。

**这一条直接服务于"梳理"：不是给你更多数据，是给你更清晰的判断。**

### ⑤ 手绘疆域 + 时间区间（"笔记本"的关键）

从"查别人的数据"变成"**画我自己的理解**"：

```
1. 从数据集里"借"一个疆域轮廓（降低手绘成本）  ← 这是数据集的新用法
2. 改成你自己的版本（"我觉得宋的北界应该在这里"）
3. 给它标确信度：确定 / 大致 / 存疑
4. 给它一个时间区间（可以是"约 960–1279"这种模糊表达）
```

> **数据集是底稿，不是答案。** 这是"笔记本"与"地图册"的根本分界。

### ⑥ 不确定性可视化

数据集里已经有 `BORDERPRECISION`（1 近似 / 2 中等 / 3 国际法确定）。
个人记忆也一样有精度：

| 确信度 | 视觉 |
|---|---|
| 确定 | 实心填充 + 实线边 |
| 大致 | 半透明 + 虚线边 |
| 存疑 | 更低透明度 + 斜纹 + 模糊光晕 |

**让"我不确定"成为一等公民。** 梳理的过程，就是把模糊变清晰。

### ⑦ 时间尺度 ↔ 空间尺度联动

- 看天下大势 → 千年 × 全国
- 看一地兴衰 → 百年 × 一省
- 看一人一事 → 十年 × 一城

**地图缩放联动时间轴缩放。** 我在公开产品里没见过。风险：可能太玄，先做原型验证。

## 五、修正后的定位与文案

### 定位（一句话）

> **Chronicles of SOI — a spacetime notebook for history.**
> **不只是看"那年世界什么样"，而是写下"我认为它怎么变的"。**

### 与现有产品的对照（可以放到落地页）

```
Geacron / Historic Borders     ：他们给你 200 张地图，你看。
Chronicles of SOI              ：你画自己的时空块，他们帮你看清结构。
```

### 建议的标语微调

原来的：
> *Chronicles of SOI is a spacetime notebook for history. Pin events on a timeline and on a map—select one, and the other follows...*

**"pin events on a timeline and on a map" 这句太弱了**——它描述的是"打点"，而打点是现有产品都有的。
建议改成强调**块**和**结构**：

> *Chronicles of SOI is a spacetime notebook for history.*
> *Draw a **span** — a period of time and a **stretch of land** — and it exists on both views at once.*
> *Overlay them, and you'll see what coexisted, what replaced what, and where your memory disagrees with itself.*

中文：
> **无知编年 · 时空笔记本**
> 你画的不是一个点，是**一段时光，和一片土地**。
> 叠加起来，你会看见谁曾共存、谁替代了谁、以及你的记忆在哪里自相矛盾。

**最后一句"你的记忆在哪里自相矛盾"是最强的卖点**——没有任何地图册会这么说，因为地图册不认为用户会错。

## 六、路线建议（修正版）

```
第 1 步（1天）  原型 → 可用的只读版
  · 政权中文名映射表
  · 年份插值（相邻快照之间渐变，而不是跳变）
  · 导出长图

第 2 步（1-2天）★ 时空重叠检测
  · 时间区间计算 + 空间相交检测
  · "曾共存"列表 + 边界高亮
  → 这一步最能让用户"啊"一声

第 3 步（2-3天）数据模型改成"块"
  · 从"年快照数组"改成"Volume[]"（每个块：name / 区间 / 多边形 / 确信度）
  · 支持手绘与编辑
  → 到这一步它才是"笔记本"，不再是"浏览器"

第 4 步（1天）  不确定性可视化
第 5 步（可选） 尺度联动
```

**注意第 3 步是分水岭。**
第 1、2 步做出来的是"一个更好的历史地图浏览器"；
**第 3 步做出来才是"时空笔记本"。**

> **我上一版给你的是一根更好的时间轴。**
